# Phone app features

- **Main screen (shell)**: `ui/shell/DanaShell` replaces the old tab bar on the phone (kiosk/TV never show `MainActivity`). Places: Now, Reminders, Notifications (badge = the overview's needs-you count, else `/api/now`'s; nothing at 0), Projects (only with `knowledge` → `docs/projects.md`), More (Shopping with the `shopping` addon → `docs/shopping.md`, Money with `money` → `docs/money.md`, Calls, People, About you → Settings; Memory only from About you). Shopping and Money take over More with their own list + stage under a "← More" link (`takeOver` in `OtherDestinations.kt`); `viewModel.addons` (`Me.addons`) decides which places and rows show. A `Destination.wide` place (Projects, Money) is drawn like SPLIT in unfolded landscape — the thread a sheet, the ask bar under the panes — so its content gets ~808dp beside the side pane; `ShellController.placeRef` is the on-screen context such a place sets (Money: `transaction` / `saving`). Layout by window width (`ShellLayout`): STACKED < 600 dp (cover: one column, list → stage drill-down, ask bar over a slim nav, thread as a sheet), SPLIT 600–899 (unfolded portrait: day strip, list | stage, thread as a sheet), FULL ≥ 900 (unfolded landscape: list + nav left, day strip over stage | thread, ask bar under the thread). All state (place, picks, thread open, ask draft) lives in `ShellController`, so fold/unfold keeps it; an unfolded auto-pick (first open reminder) is marked `auto` and does not drill in when folded.
  - **Destination contract**: a place is `Destination(place, picked, onBack, list, stage, title, kicker)` built by a `remember…Destination(vm)` function. `stage == null` means the list spans list + stage. Legacy screens hosted in a pane go inside `PaneWindow { }`, which narrows `LocalConfiguration` so they pick the layout that fits the pane. **No early `return` in a composable** (it crashed twice): branch into a child composable instead (`MoreItemStage`, `OpenReminder`, `DragChip`).
  - **Now** (`NowDestination.kt`, `ui/screens/now/`, `NowController`; server contract in `server/docs/now.md`): date + lede (+ "Updated N min ago" after a failed refresh, `NowController.updatedAt`), on the cover today's timeline from `day.slots` (`NowDay.kt`; a reminder in it opens in Reminders), "Needs you · N" cards or "All clear.", "Can wait · N" folded, the notifications line (opens Notifications) (layout in `DESIGN.md`). Cover: a tap or "More" expands the card in place (every block, choices / checks, actions); swipe towards the start = the card's dismiss, towards the end = its own first snooze (`RowActions.snooze`; none offered → nothing), both server actions with Undo. Unfolded: the first row is auto-picked, the stage (`NowStage`) shows its evidence + Decide; acting moves the pick to the next row (`NowModel.nextSelection`); nothing picked (strip's Now cell → `shell.showToday()`) = the rest of today. A `schedulable` row drags onto the day strip → `act schedule {slot}` (`NowModel.slotKeys`). Server actions go to `POST /api/now/act` optimistically (`PendingRemovals`: hidden at once, back on failure), the reply's `message` shows with Undo when it has an `undo_id` (`POST /api/undo/{id}`, 404 = too late); `device_keys` are cancelled/snoozed in the shade. Client actions (open / reply / approval review / Ask Dana / open reminder…) are handled in `NowDestination.perform`. Choice and check drafts live in `NowController` (survive fold). Refresh: on open / resume and every 60 s while Now is on screen (`NowController.startPolling`, stopped on pause, so never in the background), pull, after acting, `LiveRefresh` pings (push events, notification batches). Last payload cached in `filesDir/now_cache.json`; unreachable → "Can't reach Dana." over the cached rows. The unfolded stage's rest of today comes from the local day strip data (tasks + calendar); the cover timeline from `day.slots`. Pure rules in `NowModel.kt` and `NowDay.kt` (`NowModelTest`, `NowScreenTest`: hues by kind, swipes, header lines, timeline columns / past / next, new cards, an addon's unknown kind with `facts`). **Leading tile** (`NowTile.kt`, `NowModel.visual`): the item's notification package → that app's icon via `AppIcons`; a suggestion from a notification only has the app's name (the start of `source`, "Slack · 2 h ago"), so `AppIcons.packageForLabel` finds the launcher app by label (unique names only; needs the manifest's LAUNCHER `<queries>`); no app → a glyph by kind. A server `package` on those items would make the label lookup unnecessary.
  - **Notifications** (`NotificationsDestination.kt`, `ui/screens/notifications/NotificationsScreen.kt`, `NotificationOverviewController`) → `docs/notifications.md`.
  - **Search in the ask bar**: 2+ chars in `shell.askDraft` → `SearchController` (debounced `GET /api/search?q=`) → `SearchPane` covers the place (cover, thread closed) or fills the stage (unfolded), grouped by kind, last row "Ask Dana: “…”" (sends it as a message). `MainViewModel.openSearchResult` routes: reminder → editor, call, person, note → Projects focus, notification → its app in Notifications (the result's `package`), note → its `project_id`, shopping → opens More → Shopping.
  - **Thread** (server `docs/agent-actions.md`): one shared thread, `session_id: "main"`, for the phone, the overlay, the watch, kiosk and TV (`device` phone / watch / tablet / tv on every message and on the voice WebSocket). `ChatController` thread mode (`threadMode`, on from `initialize()`) loads `GET /api/sessions/main?limit=40` and older pages with `before=` (`ThreadModel`: `has_more`, quiet separators after `gap_minutes`), never creates or lists sessions, and answers a 409 `session_busy` calmly (the draft comes back, the busy run is followed). `undos` from the server and from `tool_end` / `state` become `UndoRows` (`POST /api/undo/{id}`; 404 = "Too late to undo that."); `shortcut` marks learned-phrase replies. Approvals opened from Now (`showConversation`) show "Another conversation · Back to the thread"; a pending approval with no card in the loaded messages still gets its Asks-first card. The cover peek row opens/closes the sheet (sheet Back closes it before the stage's Back); sending or starting the mic opens it. `AskBar` keeps its draft in `shell.askDraft`; shared text lands there. Bubbles are `ui/screens/chat/ChatBubble`. **What Dana remembers**: every thread state carries `context_from_seq` / `context_expires_at` (`ThreadModel.Memory`, absent on older servers = nothing drawn); `ThreadModel.rows` puts a "Dana remembers from here" line (`ui/screens/chat/MemoryLine`) before the first remembered message and dims the ones above; remembering nothing (just cleared, or the quiet gap ran out — re-checked on a timer and on resume) puts "New topic — Dana starts fresh" after the last stored message. The ↻ "New topic" button in the thread header (only while Dana remembers something) calls `POST /api/sessions/main/clear` (`ChatController.clearThread`; messages stay, an open prompt counts as declined, 409 while a run goes). The power-button sheet (and the kiosk / TV sheet, same overlay) draws the same line, says "Dana remembers the last conversation" when its fresh view hides remembered messages, and has the same button in its header (toast instead of Snackbar).
  - **On screen** (`ShellController` + `ScreenContext`): what the stage shows (Now pick, reminder, notification app, call, person, review) is sent with each message as `screen: {kind, id}`; "Ask Dana about this" / deep links pin a `ThreadContext(kind, id, title)` instead (it wins until × drops it). Unfolded the "On screen · …" line sits above the ask field; on the cover it is pinned at the top of the sheet (`OnScreenLine`). Activities outside the shell (debrief, suggestion pop-up, notification alert) pass `open_context_kind` / `_id` / `_title` to `MainActivity`.
  - **About you** (`ui/screens/about/AboutScreen.kt`, `AboutController`; server `docs/about.md`): facts by section (edit in place, × forgets, add line), all with Undo; "How Dana acts"; learned phrases (`/api/shortcuts`, remove = goes through the model again); self-check (`/api/checks`, "Ignore for a week" with Undo); a Settings row.
  - **Reminders**: list (`ui/screens/reminders/ReminderList.kt`: By when = Overdue / Today / When I get there / Later / Someday, or By list; quick add; Done recently folded) and editor (`ReminderEditor.kt`: title/note saved 800 ms after typing and on leave, Remind me = none / time (quick times + date/time picker) / place (HA zones, arrive/leave) / car (in/out) / waking, a sentence saying what will happen, list, priority, "Came from" task links, Done / Delete). Pure rules in `ReminderModel.kt` (`ReminderModelTest`). Every change is optimistic and goes through `TasksController.edit/setTriggers/setDone/deleteWithUndo`; complete, trigger moves and delete show Undo (delete waits for the snackbar to time out before calling the server).
  - **Day strip** (`DayStrip.kt`, SPLIT and FULL; the Now cell shows the rest of today on Now's stage): Now HH:mm, the coming hours, At home, On waking; today's events (`GET /api/calendar/events?start_date&end_date`) and the reminders that fire in each slot. Cells are drop targets: `Modifier.dragToDay(label) { slot -> … }` on any row (long-press to drag; a no-op on the cover) and `Modifier.dayDropTarget(slot)` on a cell; `remindWhenFor(slot, now, zones)` turns a slot into triggers (a past hour rolls to tomorrow).
- **Chat stream**: every assistant request is a server-side *run* whose events (`run_id` + `seq`: `step_start`, `reasoning_delta`, `text_delta`, `tool_call`, `tool_start`, `tool_end`, `final`, prompts, `run_end`) stream over SSE and close with a `state` frame. `ChatController` composes the parts that render them: `ChatRunRenderer` maps each event onto `ChatTranscript` (the messages shown: reply bubbles grow per delta, a collapsible thought block, tool cards from the moment the model picks a tool, the typing indicator) and `ChatPrompts` (approval, choice, step limit), and drops replayed events by `seq` (`RunStreamClient`); `ThreadView` holds the thread's pages, memory and fresh view, `ChatVoice` push-to-talk, `ChatUndos` the Undo row, `ChatCache` the device copy, `ChatModels` / `ChatComposer` the input. `ChatRunRendererTest` and `ThreadViewTest` pin the reduction without a network. The SSE client times out after 45s of silence (server heartbeat every 5s). If the stream drops, it reattaches with `GET /api/sessions/{id}/stream?run_id=&after=<lastSeq>` and resumes; a session loaded while `running` attaches via its `active_run`. Push-to-talk voice defaults to **live device transcription** (`data/voice/DeviceSpeech`): the system `SpeechRecognizer` (Speech Services by Google, he-IL online with he/en language switching — no offline Hebrew model exists) streams partial words into a live user bubble, ends the utterance with its own endpointing, then sends the text as a normal `/api/assistant/message`. It falls back to the server path when the recognizer is unavailable or fails before any words; Settings → "Live transcription" (pref `live_transcription`) turns it off. The server path (`/api/assistant/voice_stream`, also used by the Wear app) streams PCM and gets the same run events back over the WebSocket. The chat model (`fast`/`balanced`/`deep`, from `GET /api/assistant/models`) is picked with the chip above the input and stored in prefs `chat_model`; the Wear bridge uses it too.
- **Screen as context in the power-button sheet** (server `docs/agent-actions.md`, `device_screen`): when the system opens the sheet with assist data (`SHOW_WITH_ASSIST`), `DanaVoiceInteractionSession` keeps the screenshot (`onHandleScreenshot`) and a text description of the app in front (`onHandleAssist` → `data/screen/AssistCapture` → `ScreenText`: app label, package, cleaned window title, Chrome's URL from `AssistContent.webUri`, visible text in reading order, no password fields, lines ≤600 chars, total ≤6000) in memory for that one opening only (`ui/viewmodels/ScreenShareController`, state machine `data/screen/ScreenShare`). Nothing is sent unless the **Screen** chip is on. It is off every opening and turns itself off after one message, typed or spoken, including one already in progress when tapped. `ChatController.screenAttachments` takes it when sending. **Paths:**
  - **Typed or device-transcribed with a screenshot:** multipart `POST /api/assistant/message_with_image` with `image` (JPEG, longest side 1280, quality 80) and a `device_screen` JSON string part.
  - **No screenshot:** JSON `POST /api/assistant/message` with a `device_screen` object (never the image in `images`; that endpoint has a 1 MiB limit).
  - **Server voice WebSocket (PCM):** `device_screen` in the stop frame, no image; shown as "text only".
  - On a 409 busy, no speech or an aborted recording, the screen goes back to the chip.
  
  **What the capture can't give:**
  - The system switches (`Settings.Secure` `assist_structure_enabled` / `assist_screenshot_enabled`, read through `getUserDisabledShowContext()`) explain themselves and offer the assistant settings.
  - Secure windows (FLAG_SECURE: banking, Chrome Incognito) hand over an all-black screenshot. `BlankFrame` treats that as none, and whatever exists is sent and named.
  - Opened from Dana (`AskDanaActivity` → `showSession` with `from_dana`, or Dana's own package in front), the chip is hidden.
  
  The sent bubble shows the screenshot from `cacheDir/sent_screens/` (files older than 1h are deleted) and a "Screen · App" caption. The label survives the thread reload only for the newest user message (`ThreadModel.carryScreen`), because the server doesn't mark screen turns. The approval card says "Asking because the screen was shared." from `approval_required.reason` or the pending payload's `approval_reason` / `untrusted_content`, and "Asking because this chat holds text others wrote." for `untrusted_result` (an email Dana read) and `untrusted_context` (a chat opened from a transaction). Kiosk and TV don't pass a controller, so they keep the old dock.
- **Offline queues** (`data/sync/`): reminder Complete/Snooze (phone alarm and watch) and the Reminders editor's field edits (kind `update`, partial `PUT /api/tasks/{id}`; consecutive updates to one task merge, newer keys win) go through `TaskActionQueue`. It tries once (6s), queues to `filesDir/pending_task_actions.json` if the server is unreachable or answers 5xx, and `PendingSyncWorker` (WorkManager) or the server coming back ONLINE flushes it. Call-recording uploads run in `CallUploadWorker` (network constraint, backoff, foreground `dataSync` job, Retry action), with handled recordings remembered in `filesDir/call_uploads.json`. WorkManager is the only library that brings Room, and only internally. **WorkManager starts on demand** from `DanaApp` (`Configuration.Provider`, default process = the package; the androidx.startup initializer is removed in the manifest) so it also works in the assistant sheet's `:session` process — content providers only run in the main process, and the sheet's `MainViewModel.initialize` → Inbox sync crashed there with "WorkManager is not initialized" (7.4.1–7.8.0). The TV flavor's `DanaTvApplication` extends `DanaApp`. Still no codegen in this project.
- **Reminders**: a `reminder` push event reaches `ReminderReceiver.show`, which also forwards the alarm to the watch (`WearReminderBridge`, `/wear/reminder_alarm`). Handling it on either device dismisses the other (`/wear/reminder_dismiss` phone→watch, `/reminder_dismiss` watch→phone).
- **Reminder alarm**: `ReminderReceiver.show` opens `ReminderActivity` directly with "Display over other apps" and posts quietly on `reminders_quiet` (the screen plays the alarm itself; no heads-up over it), else `reminders_channel` + full-screen intent. `ReminderActivity` (full-screen, over the lock screen: window flags, ringing, vibration) shows `ReminderScreen` (the UI), with the dial's option tree and geometry in `SnoozeDial.kt` and complete / snooze in `ReminderActions` (through `TaskActionQueue`). It uses the same Ink & Paper tokens as the app and follows the theme setting: one-tap time snoozes plus the hold-and-drag radial dial (time / zone arrive|leave / car / wake). Keep it on theme tokens — no hardcoded colours, gradients or glows. The dial sits low and its options fan **upward** (oval rings sized to the window by `SnoozeDialGeometry.fit`) so the thumb never covers them; while dragging, a readout at the top spells out the result ("When I arrive at Home"). Drawing (`layoutSnoozeFan`) and hit-testing (`selectSnoozePath`) share one geometry — change both together and keep `SnoozeDialTest` passing (it checks every node fits the Fold cover ≈555×876 dp and inner screen at 360 dpi). Short windows (< 780 dp) get a smaller title; wide landscape (≥ 720 dp) splits into two panes (row capped at 1100 dp, the dial centred in its pane). The alert and suggestions screens cap their column (680 / 760 dp, centred) on the unfolded screen.
- **Call recordings** (off until Settings → Call recordings → "Watch for call recordings"; only Samsung's built-in recorder saves to that folder: `docs/permissions.md`): `CallRecordingObserverService` watches `Recordings/Call`. Each new file waits until it stops growing, then `RecordingInspector` (`data/sync/CallAutoUpload.kt`) reads its length (MediaMetadataRetriever) and the matching call-log entry (`READ_CALL_LOG`: direction, number, cached name). Calls ≥ `CallUploadSettings.thresholdSeconds` (10 s) upload by themselves, shorter ones post a "short call" prompt (Upload / Skip; tapping opens `ShortCallActivity`, a translucent sheet with preview playback and "Never upload calls with X"), contacts on the skip list are ignored. Settings → "Call recordings" holds the on switch (`CallUploadSettings.enabled`, gating every start through `canWatch`), the auto-upload toggle, threshold, Wi-Fi only, skip list and "Upload past recordings". After an upload `CallResultWorker` polls `GET /api/calls/{id}` until the server's analysis is done and posts the result (title, labels, pending suggestions) with a Review action into `CallDebriefActivity`.
- **Call Debrief & suggestions**: `CallDebriefActivity` (standalone, `open(context, callId)`) shows summary, editable labels, key facts and the call's suggested reminders/events as cards (Create / Edit sheet / Ask assistant / Dismiss). Pending suggestions also appear on Now and on the call detail. "Ask Dana" anywhere (suggestion, call, task) opens the shared thread with that item on screen (`shell.openThread(ThreadContext)`); the thread shows the attached item as a `ContextAttachmentCard` with quick prompts. Other activities reach the main app with extras `open_context_kind`/`open_context_id` (context chat) or `open_call_id` (select a call in Calls). Their calls and wire classes live in `data/network/CallsApi.kt`; shared UI in `ui/components/SuggestionParts.kt`.
- **Foldable sizes**: a book-style foldable has a narrow cover screen (≈ 555×876 dp, COMPACT) and a near-square inner one (≈ 821×1088 dp, 1088×821 landscape, EXPANDED). Check new screens at both, e.g. on an emulator with `adb shell wm size 1248x1972` / `1848x2448` + `wm density 360`; cap reading columns (~720 dp) and sheets (~560 dp) on the inner screen (`widthIn(max).fillMaxWidth()` — in that order).
- **Sharing**: text, links and images shared from other apps land in the ask bar of the current thread, thread open; audio still goes to Calls.
- **Boot**: `BootReceiver` restarts `CallRecordingObserverService` after a reboot or app update, when call recordings are on.
