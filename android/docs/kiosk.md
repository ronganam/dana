# Kiosk (wall tablet, `kiosk` flavor)

`io.github.ronganam.dana.kiosk` ("Dana Kiosk") runs a wall tablet as a kiosk (built on a Galaxy Tab S4, SM-T830, Android 10). Code is in `app/src/kiosk/` plus the shared wake-word source set `app/src/wake/` (package `io.github.ronganam.dana.wake`: `MicHub`, `WakeWordDetector`, `WakeWordService`, `WakeBus`/`WakePrefs`, `AssistantSession`, `DanaSpeaker`, `Chime`, and the ONNX models in `src/wake/assets/wakeword/`; the `kiosk` and `tv` flavors both add it in `sourceSets`), and reuses `MainViewModel`/`ChatController`/`FloatingAssistantOverlay` from `main`. Build + install: `bin/deploy-kiosk.sh [-s SERIAL] [--debug] [--set-home]`.

- **KioskActivity**: the HOME activity (boot, crashes and Home all land here), immersive, screen kept on. Hosts the dashboard (`<server_url><kiosk_dashboard_path>`, default `/dashboard?zoom=98`) in a WebView and the assistant overlay on top. It signs the WebView in by POSTing the API token to `/login`, which sets the session cookie. It reloads after errors and rebuilds the WebView if the renderer dies. **Only navigate once the WebView has a non-zero size**: if the first load starts at 0×0, this WebView keeps `100dvh` at 0 and the dashboard collapses. `?zoom=98` at the native DPR (2.25) looks the same as the old kiosk's `?zoom=220` at DPR 1. The page sees `window.DanaKiosk`: `openAssistant()` (the dashboard's mic button), `lux()` (the tablet's ambient light sensor, -1 with no reading) and `setBacklight(0-255 | -1)`. `setBacklight` is a window brightness override, so the dashboard's night mode dims the real backlight with no Home Assistant involved; -1 hands back to system (adaptive) brightness. While the assistant sheet is open at night, the backlight is raised to at least 20%. Hidden settings: tap the top-left corner 5 times, or `am start … --ez settings true`; it shows server/token/path, wake sensitivity and a live wake score / mic level. Other extras: `--ez assistant true`, `--ez reload true`; debug builds also take `--es inject <16 kHz mono PCM16 wav in the app's external files dir>`, which feeds the file into the mic for end-to-end tests.
- **Wake word**: `WakeWordService` (foreground, type microphone) keeps the mic open through `MicHub`: one 16 kHz AudioRecord (VOICE_RECOGNITION, AGC/NS off), 80 ms frames, a 3.2 s ring. `WakeWordDetector` is a Kotlin port of openWakeWord's streaming pipeline on ONNX Runtime: `assets/wakeword/melspectrogram.onnx` → `embedding_model.onnx` → `hey_dana.onnx`. It fires at score ≥ threshold (default 0.5) for 2 frames, with a 2.5 s debounce, and only while the overlay is closed (it resets when re-enabled). The model is trained with openWakeWord's synthetic-TTS recipe; the training workspace and config (`hey_dana.yml`) live in `~/Documents/projects/dana-wakeword`.
- **Voice turn**: always the server path (`DeviceSpeech.isEnabled` is false in the kiosk; Gemini handles Hebrew + English far-field speech). `VoiceInput.source` hands `ChatController` a stream from `MicHub` that starts at the wake frame, so words said straight after "Hey Dana" are kept. The end-of-speech threshold is 2.8× the tracked room noise floor. `VoiceInput.speechGateUntil` (700 ms) keeps the chime and the pre-roll burst from counting as speech, and speech starts only after `VoiceInput.speechStartFrames` (3 = 240 ms) loud frames in a row: a single loud frame sent near-silence to the server, and Gemini made up a sentence from it ("Hello.", "I want to order a pizza"). **Gain** (`GainStream`): far-field mics differ hugely (the TV idles at RMS ~3–6, the tablet at ~200), so the turn's audio is boosted so the room floor sits near 120 (max ×12), and the speech threshold is `GainStream.speechRatio` × the boosted floor (`GainStream.thresholdFor`): 2.5× (min 60) by default, 1.6× (min 50) on the TV, set in `DanaTvApplication`. Those TV numbers come from couch tests, after gain: silence 25–40, quiet speech 65–100, normal speech 85–120, the chime up to ~390 (gated). `adb logcat -s DanaPerf` logs each turn's room level, gain, threshold, level percentiles, longest loud run, and every frame's level (`voice turn levels:`), which is what to tune from.
- **Flow**: wake → rising chime → sheet opens (backlight ≥ 20% if the dashboard dimmed it) → listen → reply spoken by `DanaSpeaker` (picks a Hebrew or English voice by script; Hebrew needs a Hebrew TTS engine, e.g. Speech Services by Google) → listens once more for a follow-up (up to 3) → closes after 8 s idle (90 s while an approval or selection is pending). A new session starts after 2 min closed. Tapping outside the sheet or swiping it down closes it (`onMinimizeOverride`).
- The kiosk build has none of the phone-only parts (call recordings, watch bridge, system assistant/recognizer, boot receiver, install permission): they are declared in `src/phone/AndroidManifest.xml`, and the kiosk manifest only adds its own (`docs/permissions.md`).
