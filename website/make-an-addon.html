Make an add-on

Teach Dana something new.

An add-on is a folder of typed Python functions with docstrings. Dana turns them into tools it can call, cards on your Now screen and pages in the app. Four commands take one from an idea to the catalog, and a coding agent can run all four.

See the loop The reference

The loop

Edit, check, test, try.

  1. Start it

    bin/dana addons new tides writes a working add-on in its own git repository: a tool, a Now card, tests with made-up users and fakes for the model and the web, an AGENTS.md and the full reference.

  2. Check it

    bin/dana addons check tides loads it and compares what the code does with what it declares: every host it calls, every setting it reads, every tool parameter the model will see. Each problem comes with its fix.

  3. Test it

    bin/dana addons test tides runs its tests against Dana's own harness: a fresh database, two users who have it and one who doesn't, no network.

  4. Try it

    bin/dana addons dev tides starts Dana on your machine with stub services and loads it, shows its log, its tools and the cards it makes, and reloads when you save.

  5. Publish it

    bin/dana addons publish tides pushes it to GitHub, tags a release and opens a pull request to the catalog, pinned to the exact commit. Everyone running Dana can then install it from the Add-ons page.

$ bin/dana addons new tides --dir ~/code
Wrote the tides addon in ~/code/tides (a git repository)

$ bin/dana addons check ~/code/tides
error   tools.py:31  The code calls api.tides.example,
        which touches= does not list.
        fix: Add "api.tides.example" to
        touches=Touches(hosts=(...)) in addon.py

$ bin/dana addons check ~/code/tides
OK: 0 error(s), 0 warning(s)

$ bin/dana addons test ~/code/tides
PASS  tests/test_tides.py

$ bin/dana addons publish ~/code/tides
Published tides 0.1.0: the catalog pull request is open.

With a coding agent

Give it the folder. It knows the rest.

Every new add-on carries an AGENTS.md: what an add-on is, the loop above, and the rules. Next to it, REFERENCE.md lists every manifest field and every hook, each with an example taken from an add-on that Dana's own tests run. Point your coding agent at the folder and describe what you want. It edits, runs the check, fixes what the check says, and runs the tests until they pass.

The rules

Say what it touches.

  • Declare needs and touches. Every server setting it reads and every host it calls is in its manifest. People see the list before they turn it on, and the check fails when the code does more.
  • Secrets live in credentials. Keys and passwords are stored encrypted, per user. They never go in code, settings or logs.
  • Test data is made up. No real names, numbers, accounts or money in tests.
  • Each user is separate. Every tool and card runs for one person, and another person's data answers as if it were missing.
