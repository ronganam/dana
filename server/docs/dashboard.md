# Bedroom dashboard + living-room TV (server side)

The tablet runs the Android repo's `kiosk` flavor and the TV its `tv` flavor; see that repo's `docs/kiosk.md` / `docs/tv.md`.

**Cameras per user** (`addons/cameras/`: `config` the setting, `client` the Frigate logic: events rail, previews / clips, go2rtc WebRTC; handlers in `api.py`). Every `/api/frigate/*` endpoint (WebRTC signaling and the MJPEG stream included) and `/api/camera/{entity}/proxy` work for the caller's own `cameras` addon: its `url` setting is their Frigate, connected on the Addons page like every user's; without it they answer 403 `{"error": "not_connected", "addon": "cameras"}` before anything else. The two that go through Home Assistant (`/api/camera/{entity}/proxy`, the MJPEG `/api/frigate/{camera}`) need the caller's `homeassistant` too (checked first: 403 `not_connected` `homeassistant`). Events / clip caches are per connection (the clip LRU keeps 4 clips in all). Upstream paths are fixed templates: camera names must match `[A-Za-z0-9_-]{1,64}`, event ids `[A-Za-z0-9._-]{1,64}` and not only dots, motion windows are integers ≤ 60 s, and the WebRTC stream name is sent as an encoded `src` query parameter. `FRIGATE_MOTION_THRESHOLD` stays a server-wide env value.

- **Bedroom dashboard**: WebRTC camera via go2rtc (`/api/frigate/webrtc/{camera}`), **over TCP** (the page keeps only the answer's TCP ICE candidates, go2rtc's passive LAN address on port 8555; `?camtcp=0` turns this off): the tablet's Wi-Fi loses ~10% of packets, go2rtc doesn't resend them, and a 1440p keyframe is ~420 packets, so over UDP nothing ever decoded and the watchdog reconnected in a loop, climate control, battery monitors, high-priority tasks, weekly calendar strip (`/api/calendar/events`: the caller's own Google Calendar, 403 `not_connected` without the `calendar` addon). Split into `dashboard.html` + `dashboard.css` + `dashboard.js`. **Look**: the web's Ink tokens and named hues, Ink only, motion only for presses and changed values — a low-power target (`docs/web-design.md`, The bedroom dashboard). `/dashboard` is served `no-cache` with `dashboard.css/js?v=<release>` (kiosk WebViews cache `/static` aggressively, so unversioned assets never update on the tablet; the release name `<VERSION>-<commit>` changes with every deploy, so no bump is needed). Fonts (Inter) and Lucide icons are self-hosted in `static/vendor/` — no CDN at runtime. **Layout**: the top row is exactly as tall as the camera at its column width (`--main-h` from `fitCamPanel`, capped so the calendar keeps ≥ 25%), the events rail shows exactly 3 cards in equal rows level with the camera, and the week calendar takes the rest of the height (event names up to 2 lines at a distance-readable size; on a busy day the last events shrink to one compact line, then overflow behind "+N more" — `fitCalStrip`). Tapping the strip opens a near-full-screen **this week + next week** view drawn in the page itself with the same day cards (`renderWeekRow`), straight from the cached two-week fetch (`refreshCalendar`, every 5 min), so it appears instantly; data older than 1 min is refreshed in the background and re-rendered in place. Tap anywhere to close. (It used to iframe `/calendar`, which loaded its fonts and icons from CDNs and showed a blank page first.) **Night mode**: inside the kiosk app (`window.DanaKiosk`) the tablet's own light sensor (`DanaKiosk.lux()`, polled every 10 s, dark < `?nightlux=5` lx, bright again at 3×, 2 consecutive readings) decides, and night dims the **real backlight** through `DanaKiosk.setBacklight(?backlight=6)`; by day the system's adaptive brightness applies (`setBacklight(-1)`). In a normal browser, or with no sensor reading, the 22-7 schedule decides and night dims with a black overlay (`?nightdim=0.55`). `?night=23-6` forces a fixed schedule, `?night=off` disables. **Camera zoom**: one finger drags 1:1, two fingers pinch around their midpoint, wheel zooms at the cursor (pointer events, `touch-action: none`); the pan is clamped so the picture always covers the frame, and pointer deltas are divided by the page zoom so `?zoom=` doesn't change the speed. Bedside glance mode: camera and data stay live, the clock drops seconds, the layout drifts a few px (burn-in); a tap restores full brightness for 2 min. (The old Home Assistant backlight/light-sensor route is gone: no `/api/tablet/backlight`, `TABLET_NOTIFY_SERVICE` or `TABLET_LIGHT_SENSOR`.) **Events rail** (between camera and sidebar): the latest 3 items, newest first: non-audio Frigate object events, plus optional **plain motion** cards ("Motion", off unless `FRIGATE_MOTION_THRESHOLD` > 0), with GIF preview + relative age (server-clock based), refreshed every 15 s; tapping a card plays its clip in a full-screen overlay (auto-closes). Motion is camera-wide (Frigate has no per-zone motion): the server reads `/api/review/activity/motion` (30 s buckets, % of frame moving, last 24 h = continuous-recording retention), joins buckets above `FRIGATE_MOTION_THRESHOLD` (default 0 = off; sensor noise and changing light count as motion too) into segments and drops any segment within 10 s of an object event. A motion card's GIF and clip cover the segment's first minute, cut from the recordings by Frigate (`/api/frigate/motion/{camera}/{start}/{end}/preview.gif|clip.mp4`). Each item in `GET /api/frigate/events/{camera}` carries `type` (`object` / `motion`), `preview_url` and `clip_url`; object media is `/api/frigate/event/{id}/preview.gif|clip.mp4` (the caller's Frigate: the `url` setting of their `cameras` connection). **Kiosk app**: the tablet runs the Android repo's `kiosk` flavor (`io.github.ronganam.dana.kiosk`, "Dana Kiosk"), which loads `/dashboard?zoom=98` (= the old `?zoom=220` at native DPR), listens for "Hey Dana" on-device and opens the native assistant sheet over the page; voice turns use `/api/assistant/voice_stream`. Inside it the page gets `window.DanaKiosk`, and the clock card shows an **Ask Dana** mic button (`#ask-dana`, hidden in normal browsers) that calls `DanaKiosk.openAssistant()`; night mode uses `DanaKiosk.lux()` / `setBacklight()` (see Night mode).

- **Per user**: every endpoint the dashboard and the TV call answers for the request's user (the kiosk's token): `GET /api/briefing/today` their briefing (`{"briefing": null}` for a user who gets none, docs/people.md), `/api/tasks` their tasks and those of lists shared with them (403 `not_connected` without `tasks`), and the Home Assistant / calendar / Frigate endpoints below their own connections.
- **Home Assistant endpoints** (`/api/ha/state/{entity}`, `/api/ha/states`, `POST /api/ha/service`, `/api/zones`, `/api/client-config`, `/api/camera/{entity}/proxy`, the MJPEG `/api/frigate/{camera}`): each goes to the caller's own Home Assistant (host and token from their connection, `addons/homeassistant/client.py`); without the addon: 403 `{"error": "not_connected", "addon": "homeassistant"}`. `/api/client-config` returns the caller's settings (`notify_service`, `interactive_sensor`, `battery_sensor`, `person`); the bedroom dashboard reads `battery_sensor` from it.
- **Living-room TV** ("Dana TV", the Android `tv` flavor): uses `GET /api/ha/states` + `POST /api/ha/service` for its Home Assistant tiles and `/api/camera/{entity}/proxy` for camera snapshots; camera picture-in-picture plays go2rtc RTSP directly (`rtsp://<frigate host>:8554/<camera>`, which the network has to expose).
