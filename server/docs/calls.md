# Call recordings + suggestions

## Code (`addons/phone/calls/`, part of the `phone` addon)

`values` (tuning from `CALL_*` env, server-wide), `labels` (the label catalog), `store` (call rows: the owner's reads / writes, API payloads, delete), `upload` (receiving a recording), `transcription`, `context` (the owner's people / projects / tasks / lists / zones + the feedback lines), `analysis` (prompt, schema, normalisation), `suggest` (action items → suggestions), `actions` (accept / dismiss / edit / reopen a suggestion, create the task), `processing` (one call from upload to ready, startup resume), `retention`, `chat` (call / suggestion / notification cards and prompts for context chats), `tools` (agent tools; their FTS search), `backfill` (CLI). The `/api/calls/*` handlers are in `calls/api.py`, the `/api/suggestions/*` ones in `addons/phone/api.py`; context chats are dispatched by the composer `core/context_chats.py` (it also reads tasks, people and the weekly review). Tests: `bin/test test_call_pipeline`, `bin/test test_calls_users`.

## Per user

- Migration `m0014_calls_per_user`: `phone_calls` and `call_suggestions` have a `user_id` (existing calls and call suggestions went to the first admin, a notification suggestion to its notification's owner; ids, FTS rows and recordings kept). `phone_calls_fts` has no owner column: every FTS read joins `phone_calls` and filters on its `user_id`.
- An upload belongs to the request's user (dedupe by sha256 / source file name among their own calls). Every read and write takes the `User` it answers for; another user's call or suggestion id answers like an unknown one (None / "not found" / 404): detail, recording, transcript, labels, `PUT`, reanalysis, deletion, task links, context chats, the agent tools, the search box.
- Processing, reanalysis and backfill run **as the call's owner** (`users.acting_as`: usage rows are theirs); the processing semaphore (`CALL_PROCESSING_CONCURRENCY`) is server-wide. Startup resume and audio retention run for every user with `phone`, each as that user, a failing user not stopping the next (`phone/config.phone_users()` / `for_each_user`).
- The analysis prompt is built only from the owner's own addons (people, projects, open tasks, task lists, Home Assistant zones, feedback on their own suggestions) and the owner's profile (`core/user_profile.for_user(owner)`: name, other names, pronoun, context; the first admin's prompts are pinned by `tests/fixtures/calls/`). The label catalog is the same for everyone; `{first}` in a hint (partner, tech help) is the user's own first name (`labels.label_details(user, …)`).
- Suggestions (both sources) are their owner's: listed, accepted (into the owner's tasks / calendar), dismissed, edited, undone and popped up only for them. Accepting needs the addon it creates in: `tasks` for a task (403 `not_connected`), `calendar` for an event. `PUT /api/calls/{id}` refuses a `project_id` the caller cannot see (404 "Project not found"). A task link to a call (`POST /api/tasks/{id}/links {ref_type: "call"}`, `add_task(call_id=…)`) is only to one of the caller's own calls, and a call link resolves only for the call's owner.
- Without `phone`: the call tools are not offered (refused like unknown names), `/api/calls*` and `/api/suggestions*` answer 403 `not_connected`, the search box has no calls, Now / briefing / weekly review show no suggestions, and the self-check reports calls as not connected.

## Call recordings pipeline

- **Upload** (`POST /api/calls/upload`, Android auto-uploads every call ≥ 10 s and asks first for shorter ones; `upload.receive(user, …)`) returns **202** right away with `status: processing`; `processing.process_call` then transcribes (if needed; recordings over 12 MB or 12 min are cut by ffmpeg into 10-min mono Opus chunks transcribed 3 at a time and joined — inline audio is capped at ~20 MB — and a chunk that keeps failing becomes a `[mm:ss–mm:ss could not be transcribed]` line instead of failing the call; `CALL_TRANSCRIBE_*` env vars tune it), transcribes with `TRANSCRIBE_MODEL`, analyses with structured output (`CALL_ANALYSIS_MODEL`; `core/llm.py`) and sets `status: ready|failed`. Concurrency `CALL_PROCESSING_CONCURRENCY` (2); calls left in `processing` resume on startup. Re-uploads are deduped by audio sha256 / source filename among the uploader's calls (response carries `duplicate: true`).
- **Feedback loop**: `context.suggestion_feedback(user)` (in `gather_context(user)`) puts the owner's recent decisions — up to 8 accepted (with rewrites: accepting with a changed title stores `suggested_title`) and 12 dismissed per source, last 45 days — into both the call and the notification prompts. `wake` is dropped when a task already has another trigger. Suggestion API `call{}` carries the call `summary` (review sheet).
- **Labels**: fixed catalog in `addons/phone/calls/labels.py` (16 ids, max 3 per call, `GET /api/calls/labels`); editable via `PUT /api/calls/{id}`. `importance: low` marks quick/automated calls (hidden by default in the app).
- **Suggestions** (`call_suggestions`: `task|event|alert`, `pending|accepted|dismissed`): action items the owner committed to, confidence ≥ `CALL_SUGGESTION_MIN_CONFIDENCE` (0.6), fuzzy-deduped against open tasks, with triggers where they fit (time / HA zone arrive|leave / car / wake). Accept (`POST /api/suggestions/{id}/accept`, body = payload overrides, `null` clears a field) creates the task (linked to the call) or the calendar event. Agent tools: `list_call_suggestions`, `accept_call_suggestion`, `dismiss_call_suggestion`; `add_task(call_id=…)` links a task.
- **Suggestion pop-up**: when a call that just happened (`call_timestamp` ≤ `SUGGESTION_POPUP_MAX_AGE_HOURS`, default 6 — not backfills / recovered old recordings) produces suggestions (a fresh notification only with `SUGGESTION_POPUP_NOTIFICATIONS=1`; by default its suggestions wait in Now's quiet list), `phone/popups.announce_suggestions(user, source_type, source_id, heading)` pushes a `suggestions` event (`ids`, `source_type`, `source_id`, `heading`) to the owner's devices; the phone opens its review screen. `SUGGESTION_POPUP=0` turns it off.
- **Task links** (`task_links`: task_id → `call|session|whatsapp|memory|project` ref; code in `addons/tasks/links.py`): returned as `links` on `GET /api/tasks`; `POST/DELETE /api/tasks/{id}/links` (needs write access to the task). The call detail lists only the linked tasks the caller can see; accepting a suggestion creates the task for the user who accepts it (its owner).
- **Context chats**: `POST /api/chat/context {kind: suggestion|call|task|notification|person|review|transaction, id}` (`core/context_chats.start_context_session(user, …)`) creates a session of the caller whose `context` column is rebuilt into the system prompt every turn (`context_chats.session_context_prompt(user, session_id)` → `agent.run(extra_context=…)`) and returned as `context` in session state (card + quick prompts in the app). Another user's item → 404.
- **Who the prompts are about**: the owner's profile, `core/user_profile.for_user(user)` (see Per user; set with `bin/users.py update`). "Saved contacts / people" in the analysis prompt are old `memories` rows, only for a user with `people` who owns the old memories (`context.known_people(user)`).
- **Retention**: audio older than `CALL_AUDIO_RETENTION_DAYS` (90) is deleted every 6 h, per user (`retention.purge_all()`; `audio_deleted_at` set; transcript/summary kept; `/audio` → 410 to the owner).
- **Backfill**: `python -m addons.phone.calls.backfill [--user ID] [--apply] [--redo] [--limit N]` — every user with `phone` (or one), each as that user; dry-run by default; marks duplicates/unusable transcripts, labels everything, regenerates only broken titles/summaries, and creates suggestions only for future-dated items. Report → `<data dir>/call_backfill_report_<user id>.json`.
